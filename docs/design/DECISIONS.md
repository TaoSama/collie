# 设计决策

## 2026-11-25 自动化：「收件箱」放扩展会话，原来的流水改名「事件」

- **背景**：要加扩展（飞书、微信），需要一个地方列出它们的会话，并逐个决定处理哪个。原来叫「收件箱」的页签其实是 Trigger 流水，给调试用；「线程」也是同一份数据。
- **决定**：页签数不变。原「收件箱」改名「事件」，并用「事件 | 线程」分段把「线程」并进来，两者的数据和接口都不变。新的「收件箱」列出扩展的会话：宽屏左列表右详情，手机单栏；会话默认不处理，打开后才保存消息，以触发词开头的消息交给 agent。扩展本身（打开、登录、运行在哪台电脑）和全局触发词、尾标放在「接入」。
- **放弃**：把会话开关放进「接入」、收件箱完全不动（改动最小，但「在收件箱里设置处理某个会话」不成立）；新增第七个页签（手机上放不下）。
- **兼容**：本地存的旧页签 `threads` 自动转到「事件 → 线程」。

## 2026-11-25 皮肤：默认、Codex、Linear、Kami

- **背景**：要在明暗主题之外加皮肤。除了默认和 Codex，再选两套最适合 Collie 的：盯很多 agent、长时间看屏幕、手机和桌面都用，「需要你」的橙色状态要一眼看出来。
- **选了 Linear**：深色原生，靠明度分层，信息密；只有一个靛紫强调色，橙、绿、红三种状态色都很突出。
- **选了 Kami**：暖纸底长时间看不刺眼，适合以读对话为主的场景；唯一的彩色是墨蓝，不和橙色的待确认状态混在一起。两套一冷一暖、一密一松，和默认（中性）、Codex（冷灰墨色）也拉得开。
- **放弃**：GitHub Primer 的蓝色强调色和 Codex 撞色，白底又和默认太像；Claude、Cursor 的强调色是赤陶或橙红，和待确认的橙色撞车，决策卡片会不显眼；Mission Control 这类终端风只有深色；Nord 和 Linear 同属冷调，浅色的弱化文字对比度不够；shadcn 的基础色（zinc、slate、stone 等）都是近中性灰，和默认几乎一样，只用来核对 Linear 靛紫在明暗两侧的明度。
- **实现**：皮肤只覆盖变量（`docs/design/DESIGN_SYSTEM.md`），不为每个皮肤复制样式。默认皮肤的像素保持不变，只有深色下警告按钮和警告提示的文字从白色改成深色：白字在橙底上对比度只有 2.1:1。

## 2026-11-25 皮肤对齐到排版，Codex 按文字层级去掉「浅灰字」

- **背景**：皮肤只换颜色和圆角时，字体、字号、字重、行高都还是默认的样子，看起来不像对应的设计。另外界面里大量浅灰色的说明文字，显得很「AI」。
- **做法**：字体、字号阶梯、字重、行高、字距、图标、边框、按钮、输入框、分段选择器、侧栏行、卡片、气泡全部收成变量，默认值等于原来的像素，默认皮肤逐像素不变。文字颜色改为按角色写（`--t-desc`、`--t-meta` 等），皮肤按自己的设计系统给每个角色上墨。
- **Codex**：数值取自它的主题和样式。它的说明文字不少（设置行约一半带一句说明），但用 secondary（65% 墨色），比我们原来的 tertiary 深一级；tertiary 只给元信息。所以 Codex 皮肤把说明改为 secondary。它自己的界面字体不随我们分发，只把同名字体写在栈首，本机装了才生效，否则用系统字体。
- **Linear**：自托管 Inter（SIL OFL，拉丁子集约 68KB，`font-display: swap`，用这个皮肤时预加载）。强调字重用 500 而不是它的 510：超过 500 时中文回退字体会跳到半粗体。
- **Kami**：按它的规范全用衬线体（中文宋体系，不打包字体），只用 400 和 500 两种字重，不用斜体，阴影只留一层很淡的投影。
- **这轮没动**：默认、Linear、Kami 的说明文字仍是原来的浅灰（对比度约 3.3–3.9:1）。

## 2026-11-25 皮肤不得改变内容和功能

- **背景**：Codex 皮肤一度隐藏了 Codex 界面里没有的文字（页面副标题、介绍段落、启动表单提示、「点终端即可输入」、侧栏会话的第二行），人发现有些字不见了。
- **决定**：皮肤只改设计元素，不改内容和功能；每个皮肤的可见文字必须和默认皮肤完全相同。隐藏这些文字的规则全部删掉，降低「灰字感」只靠颜色层级、字重和字号。
- **验证**：用脚本对 4 个皮肤 × 浅/深 × 桌面/手机 × 各页面采集可见文本，和默认皮肤逐页比对，必须一致。

## 2026-11-25 回复串：主聊天只留第一条和最新一条

- **背景**：在和 Collie 的聊天里，你和 Collie 用引用一来一回，一个话题会把主聊天刷满。想把同一串收起来，又不能让新回复从主聊天里消失。
- **怎么算一串**：边就是消息的引用（`re.entry`）：你引用 Collie，或 Collie 用 `--re` 回你（触发事件会解析回你那条）。引用 worker、事件或定时的不算。第一条加回复至少 3 条才算一串。第一条太早没加载时，按引用里的原文算进去（`web/threads.js`）。
- **选了**：第一条留在原位，最新一条留在它说出来的位置，中间的收起，最新一条下面加一行「↳ N 条回复 ›」，点开在右侧看整串。新回复总在主聊天底部露出来，所以不需要未读点。你在主聊天或抽屉里回了之后，你那条先显示在主聊天；Collie 回了以后，你那条收起来，留在 Collie 回复的引用行里。抽屉里发的消息自动引用这串最后一条，所以后端允许引用你自己的消息。
- **放弃**：只在每段末尾加入口、不收起任何消息，这样还是会刷屏；只留第一条、整串收进一行（Slack 式），这样 Collie 的新回复会停在很早的位置，滚在底部时看不到，只能靠未读点补救。
- **抽屉**：桌面是对话右侧的一栏，可以拖宽，宽度会记住，和文件栏可以同时开；手机全屏从右侧滑入。消息、快捷回复、钉住和复制都和主聊天共用同一套渲染和事件，SSE 更新时一起重绘。
